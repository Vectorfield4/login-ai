# i18n — two languages, build-time translations

The site is bilingual: Russian (default) and English. Translations never come
from the network and never load at runtime — dictionaries live in the repo and
compose into a typed object at build time.

## Rule

Every new component, page and content block ships in both languages at once.
User-facing text is never hardcoded: a block receives keys (or an array of keys)
and translates them itself. A missing translation on either side is a bug, not a
detail.

## Where keys live

| What | Where |
|---|---|
| UI and page copy | `src/shared/i18n/ru/<ns>.ts` + `src/shared/i18n/en/<ns>.ts` — mirrored files per namespace |
| Entity copy | `src/entities/<slice>/i18n/<plural>.ts` — `casesRu`/`casesEn`, `servicesRu`/`servicesEn`, `solutionsRu`/`solutionsEn` |
| Full dictionary | `src/shared/i18n/dict.ts` — `astroDictRu` / `astroDictEn`, spreading shared namespaces plus entity dictionaries |
| Facade | `src/shared/i18n/t.ts` — `createT(lang, astroDicts)`: dotted key lookup plus `{{var}}` and `{var}` interpolation |
| Hook | `src/shared/hooks/useT.ts` — `useT(lang)` over the same facade |

`shared/i18n` namespaces: `ui`, `home`, `servicesPage`, `servicePage`,
`solutionsPage`, `solutionPage`, `casesPage`, `casePage`, `contactsPage`,
`investorsPage`, `newsPage`, `showcase`, `audiences`, `technologies`,
`relevants`, `notFoundPage`.

A key lands in BOTH files in the same commit. Dictionary types are plain
`typeof` without `as const` — a recursive `Widen` is deliberately not used.

## A component takes `lang`, never a translator

A component accepts `lang: AppLang` and builds its own translator:

```tsx
function Card({ lang }: { lang: AppLang }) {
  const t = useT(lang);
  return <p>{t("ui.readMore")}</p>;
}
```

An `.astro` page still creates a translator for itself
(`createT(currentLang, astroDicts)`) and passes **only `lang`** down the tree.
There are no exceptions: the rule covers the whole component layer, islands
included.

The reason is prop serialization — see "Islands and props" in `ssg.md`. The
guards need no file list, so a new island adds nothing to maintain:

- the translator type is not exported from `shared/i18n/t.ts`, so it cannot be
  imported for a prop — the compiler says no;
- `biome.json` → `style/noRestrictedImports`: component layers (`entities`,
  `features`, `widgets`, `shared/ui`) may not import `createT`/`TFunc` or
  `astroDicts`; the exemptions are declared as globs in `overrides` and cover
  only the i18n wiring (`shared/i18n`, `shared/hooks`, `shared/data`) and tests;
- `npm run verify:dist` looks for `[0,null]` inside `<astro-island>` props in
  the built HTML, so any function reaching a prop fails the release.

## Switching

The toggle is `LanguageToggle` in the AppBar. Language lives in
`localStorage["lang"]`, theme in `localStorage["theme"]`. The current language
reaches `BaseLayout` as the `lang` prop and lands in `<html lang>`.

## Parity

`test/astro-content.test.ts` imports `astroDicts` from `@/shared/i18n/dict` and
compares the RU and EN key paths namespace by namespace. A new namespace without
an English mirror fails the suite.
